# 电机驱动停止与初始化核对

2026-10-12。当前电机板仍未确认型号、针序和负载；TB6612FNG 是候选，不是已装配事实。本文对应已有 `dc_motor_pwm` 驱动和 V0.4 扩展板，不改变原理图、BOM、预算或制造资格。

## 初始化修复

旧驱动先切换 IN1/IN2 为输出，再写停止电平和零占空比；没有先关闭已有 PWM 通道。新增主机回归用高 ODR、非零比较值及已使能通道复现了顺序错误，旧代码在 GPIO 配置处断言失败。

现在的顺序是：校验两条独立单引脚绑定；清比较值；请求 HAL 停止该 PWM 通道；只有 HAL_OK 后才启用 GPIO 时钟、预置两脚 ODR 低，再配置输出。HAL_BUSY/HAL_ERROR/HAL_TIMEOUT 不继续配置方向脚，返回 DC_MOTOR_ERROR_HAL；句柄 initialized 保持 0，不能 Start/SetSpeed/Task/SetStopMode。有效初始化完成才置 1。

调用方必须先完成定时器配置、将句柄初始置零、保持实际执行器电源/信号禁止，并检查 Init 返回值。失败不是物理停止证明：旧通道可能未停，GPIO/功率状态仍须靠独立门禁约束。应用现有初始化先撤销 ACT_EN，电机失败置 MOTOR 故障并保留安全锁定，不允许忽略故障后直接恢复运动。驱动不能在带电机构上热重初始化。

## 零速输入不等于机械停止

公共 API 的 DC_MOTOR_STOP_COAST/BRAKE 改为 **DC_MOTOR_STOP_INPUTS_LOW/HIGH**。它们只选择零速时的两个方向脚电平，比较值仍为 0；不保证物理高阻滑行、制动或切断能量。DC_Motor_SetStopMode 现在返回状态码，拒绝未初始化/无效句柄和未定义模式，调用方应检查结果。当前工程没有旧模式名的调用，默认仍为两个输入低，没有自动切换停止电平。

对照 [Toshiba 当前 TB6612FNG 资料](https://toshiba.semicon-storage.com/info/TB6612FNG_datasheet_en_20141001.pdf?did=10660&prodName=TB6612FNG)（网页当前版本 2026-05-13，第 4 页），其定义的关键状态为：

| STBY | IN1/IN2 | PWM | 芯片规定的行为 |
|---|---|---|---|
| 低 | 任意 | 任意 | 两输出高阻待机 |
| 高 | 两个输入低 | 高 | 两输出高阻停止 |
| 高 | 两个输入高 | 任意 | 两输出拉低的短路制动 |
| 高 | 相反电平 | 低 | PWM 低相位为短路制动 |

**两个输入低、PWM 低不能直接套用上表高阻停止行。** HAL 比较值为零、停止定时器通道和驱动芯片端实际 PWM 电平也不是同一证据。因此不会通过把 PWM 改成 100% 来临时补所谓滑行停止，或依赖未知模块电路代替 STBY/断能设计。

## 与现有草案的接口

总板 U7 的 A2 接 VLOGIC_3V3，B2Y 经 STBY_OUT 到 J6 逻辑第 7 脚；OE 接 SIGNAL_EN，R44 对 STBY_OUT 下拉。它是外部门禁配合的待机路径，不是单独的 MCU STBY 命令，也不是现用驱动模块排针。主控仍只提供 PWM/IN1/IN2 三条电机控制信号。

BabyCare_StopOutputs 先撤销 ACT_EN，再清软件电机目标/停止 PWM。只有实际隔离、下拉、门禁响应和模块 STBY 连接验收后，才可能以这条硬件路径支持断能结论；现有未验证的 V0.4 不能通电。软件零速、50ms 换向等待和状态日志不证明转子已停，不能当作制动时间或机械行程保护。
