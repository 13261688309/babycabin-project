## 二、本次实际验证结果

### 固件

- 完整 Debug 与 Release 编译、链接通过，启用 `-Wall -Wextra -Werror`。
- 八组原生产 C 模块回归通过：状态判定、报文边界、电机换向、舵机轨迹/软限位、串口队列/恢复、ESP32 配置确认、后台发送、应用安全门禁。
- USART1 使用 4 个普通槽位与 2 个独立告警槽位，报文在入队时复制；当前报文发送完后优先发告警，不在半行中间插入另一报文。成功入队不等于物理送达。
- 发送启动失败退避 10 ms，最多尝试 3 次后丢弃；在途发送超过 200 ms 则取消，成功取消后先发送换行，避免接收端把断帧和下一条 JSON 拼接。取消失败时不复用在途缓冲区。
- USART1 发送中断优先级为 6，低于语音和 ESP32 接收的 5；回调只发布完成/错误标记，队列处理在主循环执行，不使用 DMA。状态日志增加丢弃、启动错误和超时计数。
- USART2 五字节语音帧与 USART3 配置/IP 查询也使用中断发送；各自持有发送缓冲区至完成，忙时不覆盖在途数据，200 ms 超时后取消。ESP32 配置步骤现在要求发送完成和独立 OK 应答同时满足；3 s 应答超时、fail 拒绝或接收错误终止本轮配置。在途或可能已经生效的命令不自动重放，仅未启动发送最多重试 3 次。
- 新增整套配置回归：六步成功应答、回调前 OK 保留、无换行/伪 OK/隐藏 NUL/超长行拒绝、ACK 到达与消费时刻分离、截止边界、计时回绕、等待 ACK 时 STOP 优先，以及失败取消不释放在途缓冲区。应答不含命令 ID，实机换行规则与跨步骤延迟重复包关联仍待解决。
- 状态日志新增 `esp_cfg_result/esp_cfg_ack_timeout/esp_cfg_reject`，512 字节缓冲区仍检查截断。结果 2 只表示六步均获应答，不代替配置读回或联网验证。
- 模拟发送在途时触发 STOP，电机和双舵机输出关闭，发送仍保持在途；未据此声称任何毫秒级物理停止指标。
