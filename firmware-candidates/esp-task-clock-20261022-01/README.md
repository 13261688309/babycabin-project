## 已复现的问题

正式 `ESP32Cam_Task` 在处理 TX/ACK 前读取 `now`，在后面的临界区内按接收中断更新的时间戳判断过期。若期间跨越一个 tick，UART 中断可把接收时间更新到 `now + 1`。无符号差值于是成为很大的正数，而不是数据刚到达。

主机注入在屏蔽中断前发生的 UART 回调，原代码可确定性复现三种结果：

- `$STOP#` 的首段刚收到，就被任务当作过期残帧清除，后续部分不能组成 STOP。
- 刚收到的 AP 地址立即失效。
- 刚收到的 STA 地址立即失效。

舵机命令和另一种 `$7,0,0,0#` STOP 编码也在覆盖范围内。这不是把任意畸形数据当 STOP 的理由，也不以软件串口 STOP 替代独立物理停车。

## 修复范围

只在接收状态老化的临界区中、屏蔽中断之后重新读取 `HAL_GetTick()`，再统一检查 AP/STA 和半帧。保持原有阈值 250ms/15000ms、命令格式、STOP 队列优先级、引脚、默认开关及 STOP/ARM/PG/看门狗逻辑。

当前 H743 HAL 的 `HAL_GetTick()` 只返回 `uwTick`，该检查不调用延时、等待或通信。以后若覆盖此弱函数，需要重新审查它是否可在临界区内使用。
